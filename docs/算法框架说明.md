# Imperative Navigation 算法框架

本文档说明本项目从传感器输入到速度指令输出的主要算法链路。项目的核心算法来自
`src/imperative_navigation/algorithm/Imperative_learning_2D_moving.py`，ROS 2 节点负责把
LaserScan、里程计和 TF 接入该算法，并把规划结果发布给 Gazebo 或 Rosmaster M1。

## 1. 系统分层

```text
LaserScan + Odometry/TF
          │
          ▼
  ROS 适配层：坐标转换、时效检查、急停检查
          │
          ▼
  点云预处理与障碍物检测
    ├─ 激光点聚类
    ├─ 点簇质心与尺寸估计
    └─ 墙面点簇过滤；原始激光点始终保留
          │
          ▼
  Kalman 多目标跟踪与动态/静态判别
          │
          ├──────────────► 位姿辅助的点地图
          │
          ▼
  速度/位置预测 + 滚动时域候选轨迹评价
          │
          ▼
  选出下一步加速度 → 速度积分 → 机体坐标系速度
          │
          ├─ Gazebo: /cmd_vel
          └─ 实机: /imperative/cmd_vel_raw → 看门狗 → /cmd_vel
```

项目不是 Nav2 的全局路径规划器。它使用当前局部观测和一个短时滚动时域，在每个控制周期
重新选择下一步加速度；目标点以 `/odom` 坐标系中的二维坐标表示。

## 2. ROS 节点与职责

| 节点/文件 | 作用 | 运行场景 |
| --- | --- | --- |
| `imperative_controller` / `controller_node.py` | 使用 `/scan`、`/odom`，输出 `/cmd_vel`，并发布规划路径和障碍物 Marker | Gazebo 或通用仿真 |
| `imperative_m1_controller` / `m1_controller_node.py` | 使用实机 `/scan`、`/odom` 和 `odom -> laser` TF，输出原始速度 | Rosmaster M1 实机 |
| `imperative_cmd_watchdog` | 接收 `/imperative/cmd_vel_raw`，新鲜时转发，超时或未收到指令时持续发布零速度 | 实机安全链路 |
| `software_lidar` | 根据 Gazebo 里程计和仿真障碍物中心进行 667 线、6 Hz 二维射线检测，发布 `/sim_scan` | WSLg/Gazebo LiDAR 兼容层 |
| `dynamic_obstacle_mover` | 移动仿真障碍物，并发布 `/imperative/dynamic_obstacles` | Gazebo |

算法源文件通过 `algorithm_loader.py` 从已安装的 ROS 包中加载，因此构建后修改源代码时建议使用
`--symlink-install`，并重新构建或确认安装目录指向当前源文件。

## 3. 单个控制周期

### 3.1 输入检查与坐标转换

Gazebo 适配器直接使用 `/odom` 中的机器人位置和航向，将 LaserScan 的极坐标转换为二维点；实机
适配器还会通过 TF 把激光点转换到 `/odom` 坐标系。实机模式会拒绝以下输入：

- `/scan` 或 `/odom` 尚未到达，或消息超过默认 `0.50 s`；
- `odom -> laser` TF 不存在，或 TF 年龄超过默认 `0.30 s`；
- LaserScan 没有有效回波；
- 最近激光回波小于等于默认 `0.45 m` 的 `emergency_stop_distance`。

以上任意情况都会发布零速度。控制周期的 `DT` 不是盲目固定为 `0.1 s`：适配器用相邻规划回调
的实际经过时间更新 `DT`，并限制在 `0.05~0.50 s`，这样在实机计算较慢时，速度和动态障碍物预测
不会仍按过期的 0.1 秒进行积分。

### 3.2 激光点聚类与几何检测

`scan_to_cluster_detections()` 首先只保留有效激光回波，并把激光点转换为 `/odom` 下的世界点。相邻回波
满足以下条件时归入同一簇：

- 激光束索引连续；
- 相邻点欧氏距离不超过 `CLUSTER_GAP = 0.30 m`。

首尾相邻的激光簇会做环绕合并。每个至少包含 3 个点的点簇直接计算质心；障碍物半径取点到质心
距离的 P90，再增加 `0.08 m` 余量，并限制在 `0.10–0.60 m`。包围盒对角跨度超过 `1.20 m` 的
点簇按墙面或大型静态结构处理，不创建动态检测结果。

无论点簇是否进入跟踪器，全部有效激光点都会进入当前帧碰撞检测和点地图。因此墙面过滤只影响
动态目标跟踪，不会让规划器忽略墙面或大型障碍物。

### 3.3 障碍物跟踪

`update_tracks()` 为每条轨迹维护状态 `[x, y, vx, vy]` 和 `4×4` 协方差。每周期先按匀速模型
执行 Kalman 预测，再将全部 track-detection 距离从小到大排序，完成一对一全局最近邻关联。关联
门限为 `0.80 m`，匹配后用点簇质心执行位置观测更新。

- 位置观测噪声标准差 `0.08 m`；
- 过程加速度标准差 `0.8 m/s²`；
- 估计最大速度 `1.0 m/s`；
- 最多允许丢失 `5` 个扫描周期。

ROS 适配层还使用 `ConfirmedTrackFilter`：轨迹至少观测 `3` 次且当前没有 miss 才进入动态预测；
位置不再经过二次 EMA。速度低于 `0.25 m/s` 的已确认轨迹会按静态障碍物处理；连续 3 帧达到
动态速度阈值后才启用未来运动预测。原始激光点不会因为轨迹尚未确认而被忽略。

### 3.4 位姿辅助点地图

`update_slam_map()` 将当前世界坐标点累积到 `map_points`，再按 `0.10 m` 栅格去重，并限制为
最多 `2000` 个点。已确认的动态障碍物轨迹历史及其当前中心会从地图中剔除，避免移动物体在地图
中留下“墙”。

这里的“SLAM map”是轻量的位姿辅助点地图，不包含回环检测、重定位或完整的 SLAM 后端；它依赖
`/odom` 提供的位姿把连续扫描放入同一坐标系。

### 3.5 滚动时域加速度规划

`select_acceleration()` 使用 `PLAN_HORIZON = 10` 个离散步进行短时预测；默认 `DT = 0.1 s`，
对应 `1 s` 时域。每个候选计划按当前
`DT` 积分速度和位置，并对速度、加速度分别施加上限。候选计划包括：

- 上一周期计划向前移一格的 warm start；
- 当前速度的制动计划；
- 先加速后减速的 move-and-stop 计划；
- `36` 个方向上的恒定加速度计划，候选加速度幅值为最大加速度的 `0.25、0.50、1.00`；
- 一条直接指向目标的加速度计划。

每个候选计划的总代价由三部分构成：

1. 目标位置代价：鼓励预测终点靠近 `GOAL`；
2. 目标速度代价：到达目标时尽量减速；
3. 加速度代价：抑制过大的控制量；
4. 障碍物碰撞代价：对预测机器人与动态轨迹、当前激光点、历史点地图和仿真边界的近距离进行
   高权重惩罚。

其中碰撞安全半径为 `ROBOT_RADIUS + SAFETY_MARGIN`，并在规划代价中额外使用
`PLANNING_CLEARANCE_MARGIN = 0.15 m`。碰撞代价权重为 `100000`，明显高于目标位置权重 `100`
和目标速度权重 `20`，所以候选轨迹首先要满足安全距离，再比较到目标的效果。

仿真模式使用世界边界 `x∈[-4.0, 4.0]、y∈[-3.2, 3.2]`。实机模式会关闭这组人工边界，真实墙体
和物体由激光点提供。

### 3.6 速度输出

选出的第一步加速度通过 `step_robot()` 更新当前速度，并限制在 `MAX_SPEED` 内。规划在世界坐标系
中进行，发布前根据机器人 yaw 转换为机体坐标系的 `Twist`；M1 使用平移速度 `linear.x/y`，规划器
不主动注入角速度。

实机输出还经过两道保护：

- `enabled=false` 时继续感知、跟踪、规划和可视化，但只输出零原始速度；
- 看门狗默认以 `20 Hz` 发布，超过 `0.60 s` 没有新原始指令就强制向底盘 `/cmd_vel` 发布零速度。

## 4. 仿真与实机的差异

### Gazebo

`imperative_m1_gazebo.launch.py` 会同时启动 Gazebo Sim、ROS-Gazebo bridge、动态障碍物、规划器和
RViz。默认使用 Gazebo `gpu_lidar`，规划器订阅 bridge 转发的 `/scan`。如果 WSLg 的 GPU 雷达
初始化失败或所有光束饱和，设置 `software_lidar:=true`；此时模型不生成 GPU 雷达，软件节点以同样
的 667 线、12 Hz、0.05–12 m 参数发布 `/sim_scan`，规划器自动切换订阅话题。两种输入都会进入同一
套扫描聚类、跟踪、点地图和滚动规划流程。

动态障碍物默认采用连续平滑随机运动：控制器随机更新目标速度，并通过加速度限制改变速度和方向；
`dynamic_motion_mode:=random_waypoint` 可恢复固定速度的随机目标点模式。

Gazebo 机器人来自 `src/yahboomcar_description/urdf/yahboomcar_M1_gazebo.urdf.xacro`：视觉使用
Yahboom M1 原厂 STL，底盘使用 Gazebo `MecanumDrive`，里程计使用 `OdometryPublisher`。为避免复杂
STL 碰撞网格拖慢物理仿真，Gazebo 专用描述中的碰撞几何是等尺寸的简单盒体和圆柱体；这不影响视觉
模型、关节名称、雷达安装位姿或算法接口。

### Rosmaster M1 实机

`imperative_m1_real.launch.py` 只接受实机 `/scan`、`/odom` 和 TF，不使用 Gazebo 障碍物真值，也没有
仿真边界。规划器发布到 `/imperative/cmd_vel_raw`，独立的 watchdog 才是 `/cmd_vel` 的项目发布者。
实机启动前必须先启动底盘、EKF、激光和 TF；第一次测试建议保持 `enabled=false`，确认传感器和规划
日志正常后，再在空旷区域显式设置 `enabled:=true`。

## 5. 主要参数

| 参数 | 仿真默认值 | 实机默认值 | 含义 |
| --- | ---: | ---: | --- |
| `max_speed` | `1.0 m/s` | `0.18 m/s` | 速度上限 |
| `max_acceleration` | `1.0 m/s²` | `0.25 m/s²` | 加速度上限 |
| `robot_radius` | `0.15 m` | `0.18 m` | 机器人碰撞几何半径 |
| `safety_margin` | `0.15 m` | `0.18 m` | 规划额外安全裕量 |
| `control_period` | `0.1 s` | `0.1 s` | 控制器请求周期 |
| `trajectory_horizon` | `10` | `10` | 规划预测步数，默认对应 `1 s` |
| `goal_x/goal_y` | `2.5/1.5` | `1.0/0.0` | `/odom` 坐标系中的目标点 |
| `enabled` | 不适用 | `false` | 实机物理输出开关 |
| `emergency_stop_distance` | 不适用 | `0.45 m` | 最近激光回波触发零速 |

调整 `robot_radius` 或 `safety_margin` 时，应同时考虑真实车体尺寸、激光安装位置和制动距离；
`emergency_stop_distance` 是独立的最终激光急停阈值，不会自动由前两个参数推导。

## 6. 可视化输出

规划器在 `odom` 坐标系发布：

- `/imperative/planned_path`：当前选中滚动计划的预测路径；
- `/imperative/tracks`：已确认障碍物轨迹的 MarkerArray；
- `/imperative/obstacle_centers`：实机适配器额外发布的障碍物中心 PoseArray。

Gazebo 启动文件默认打开 `rviz/imperative.rviz`，其中包含 LaserScan、规划路径、障碍物轨迹和
里程计显示。
