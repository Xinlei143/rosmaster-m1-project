# 常见运行命令

本文档以仓库根目录
`/home/xinlei/Data/ROS/rosmaster-m1-project` 为例，命令适用于 ROS 2 Humble。所有终端在运行
ROS 2 命令前都应先加载 ROS 环境和本项目的 `install` 环境。

## 1. 首次构建与环境准备

在仓库根目录执行：

```bash
cd /home/xinlei/Data/ROS/rosmaster-m1-project
source /opt/ros/humble/setup.bash
export PYTHONPATH=/usr/lib/python3/dist-packages${PYTHONPATH:+:$PYTHONPATH}
/usr/bin/colcon build \
  --packages-select yahboomcar_description imperative_navigation \
  --symlink-install
source install/setup.bash
```

构建阶段使用系统 `/usr/bin/colcon` 和 ROS 的系统 Python 依赖；运行节点时再按环境说明配置
`pendulum-rl` 中的 `torch`、`numpy`。本项目的 ROS 节点运行时必须能够同时导入 `rclpy`、`torch`、
`numpy` 和其他依赖。

每个新终端都需要重新执行：

```bash
source /opt/ros/humble/setup.bash
source /home/xinlei/Data/ROS/rosmaster-m1-project/install/setup.bash
```

检查包是否已被 ROS 找到：

```bash
ros2 pkg prefix imperative_navigation
ros2 pkg executables imperative_navigation
```

## 2. Gazebo 仿真（推荐入口）

该 launch 会启动 Gazebo Sim、ROS bridge、M1、静态/动态障碍物、规划器和 RViz：

```bash
cd /home/xinlei/Data/ROS/rosmaster-m1-project
source /opt/ros/humble/setup.bash
source install/setup.bash
ros2 launch imperative_navigation imperative_m1_gazebo.launch.py
```

默认目标是 `(2.5, 1.5)`，默认开启 RViz，并使用 Gazebo `gpu_lidar`。仿真模型由
`yahboomcar_description/urdf/yahboomcar_M1_gazebo.urdf.xacro` 生成，外观来自 Yahboom M1 STL，底盘
运动由 Gazebo 的 `MecanumDrive` 插件负责。

动态障碍物默认使用 `dynamic_motion_mode:=continuous`，速度和方向会按随机时间平滑变化；
`dynamic_motion_mode:=random_waypoint` 可恢复旧的固定速度随机目标点巡逻。

默认雷达参数与实机 T-MINI PLUS 对齐：667 线（约 0.54°）、6 Hz、0.05–12 m、0.01 m 距离分辨率。

常用仿真变体：

```bash
# 只运行 Gazebo/规划器，不打开 RViz
ros2 launch imperative_navigation imperative_m1_gazebo.launch.py rviz:=false

# 无 Gazebo GUI，适合只观察 ROS 话题或远程运行
ros2 launch imperative_navigation imperative_m1_gazebo.launch.py gui:=false

# 降低速度和加速度，模拟更保守的实机参数
ros2 launch imperative_navigation imperative_m1_gazebo.launch.py \
  max_speed:=0.20 max_acceleration:=0.50 \
  robot_radius:=0.18 safety_margin:=0.10

# WSLg/GPU LiDAR 异常时切换到同参数的软件雷达后备
ros2 launch imperative_navigation imperative_m1_gazebo.launch.py \
  software_lidar:=true
```

`software_lidar:=false` 时，规划器使用 bridge 转发的 Gazebo `/scan`；`software_lidar:=true` 时，
模型不生成 GPU 雷达，软件节点发布同参数的 `/sim_scan`，规划器自动改订阅 `/sim_scan`。
如果 `/scan` 几乎全为最小量程，优先切换到后备模式。

## 3. RViz 单独运行

Gazebo launch 默认已经启动 RViz。如果需要单独启动 RViz，先确保已有节点正在发布话题：

```bash
source /opt/ros/humble/setup.bash
source /home/xinlei/Data/ROS/rosmaster-m1-project/install/setup.bash
rviz2 -d /home/xinlei/Data/ROS/rosmaster-m1-project/install/imperative_navigation/share/imperative_navigation/rviz/imperative.rviz
```

默认配置使用：

| RViz 显示 | 话题 | 固定坐标系 |
| --- | --- | --- |
| 激光 | `/scan` | `odom` |
| 规划路径 | `/imperative/planned_path` | `odom` |
| 障碍物轨迹 | `/imperative/tracks` | `odom` |
| 里程计 | `/odom` | `odom` |

软件 LiDAR 仿真时，若要在 RViz 中查看软件扫描，需要把 LaserScan 显示的话题从 `/scan` 改为
`/sim_scan`；规划器本身在该模式下已经自动订阅 `/sim_scan`。

## 4. M1 模型与雷达文件

当前仿真只接入 Yahboom M1 描述，不需要额外的 `ros2_control` 控制器：

```text
src/yahboomcar_description/urdf/yahboomcar_M1.urdf.xacro
    原厂 M1 URDF/Xacro
src/yahboomcar_description/urdf/yahboomcar_M1_gazebo.urdf.xacro
    Gazebo MecanumDrive、OdometryPublisher 和雷达扩展
src/yahboomcar_description/meshes/M1Mecanum/
    原厂 M1 外观 STL
```

Gazebo 专用文件保留原厂 STL 作为视觉外观，但使用简单盒体/圆柱体作为碰撞几何，以保证 Gazebo
物理引擎实时运行。启动时 `robot_state_publisher` 展开 Xacro，`ros_gz_sim create` 将模型放入
原来的 `imperative_m1.sdf` 世界。

雷达统一使用实机 T-MINI PLUS 参数：

```text
667 线，约 0.54°，6 Hz，0.05–12 m，0.01 m 距离分辨率
```

默认 `software_lidar:=false`，使用 Gazebo `/scan`。如果 WSLg GPU 雷达异常，使用：

```bash
ros2 launch imperative_navigation imperative_m1_gazebo.launch.py \
  software_lidar:=true
```

此时会关闭模型内 GPU 雷达，由软件节点以相同参数发布 `/sim_scan`，规划器会自动切换到该话题。

## 5. Rosmaster M1 实机部署

实机运行前，先在底盘/传感器终端启动厂家提供的 M1 底盘、EKF、YDLidar 和 TF launch。需要确认
项目能收到以下接口：

```text
/scan                  sensor_msgs/LaserScan
/odom                  nav_msgs/Odometry
odom -> laser 的 TF
底盘订阅 /cmd_vel      geometry_msgs/Twist
```

厂家 launch 的具体文件名取决于本地 `yahboomcar_ros2_ws` 配置，不能由本项目自动推断。启动厂家
工作空间后，在本项目终端加载两个工作空间：

```bash
cd /home/xinlei/Data/ROS/rosmaster-m1-project
source /opt/ros/humble/setup.bash
source /path/to/yahboomcar_ros2_ws/install/setup.bash
source install/setup.bash
```

### 4.1 先启动独立看门狗

看门狗必须在单独终端持续运行，而且应先于规划器启动：

```bash
cd /home/xinlei/Data/ROS/rosmaster-m1-project
source /opt/ros/humble/setup.bash
source /path/to/yahboomcar_ros2_ws/install/setup.bash
source install/setup.bash
ros2 launch imperative_navigation imperative_cmd_watchdog.launch.py
```

默认行为是：收到新鲜的 `/imperative/cmd_vel_raw` 时转发到 `/cmd_vel`；超过 `0.60 s` 没有新指令
时，以 `20 Hz` 持续发布零速度。停止规划器终端后不要停止看门狗终端。

确认它是 `/cmd_vel` 的唯一项目发布者：

```bash
ros2 topic info /cmd_vel --verbose
```

如果还有手柄、键盘遥控或其他节点发布 `/cmd_vel`，应先停止它们，否则多个发布者会争抢底盘控制权。

### 4.2 dry-run 运行（推荐首次测试）

实机规划器默认 `enabled=false`。它会处理传感器、跟踪、规划和可视化，但不会让小车移动：

```bash
cd /home/xinlei/Data/ROS/rosmaster-m1-project
source /opt/ros/humble/setup.bash
source /path/to/yahboomcar_ros2_ws/install/setup.bash
source install/setup.bash
ros2 launch imperative_navigation imperative_m1_real.launch.py \
  goal_x:=1.0 goal_y:=0.0 enabled:=false
```

检查 `/scan`、`/odom`、TF 和规划日志均正常后，再进行低速实机测试。

### 4.3 启用实机运动

只有在空旷区域、确认看门狗是唯一 `/cmd_vel` 发布者，并确认目标坐标位于当前 `/odom` 帧后，才显式
开启运动：

```bash
ros2 launch imperative_navigation imperative_m1_real.launch.py \
  goal_x:=1.0 goal_y:=0.0 enabled:=true
```

`goal_x` 和 `goal_y` 是 `/odom` 中的绝对坐标，不是“从当前点前进多少米”。运行前可查看当前位姿：

```bash
ros2 topic echo /odom --once
```

更保守的低速测试参数示例：

```bash
ros2 launch imperative_navigation imperative_m1_real.launch.py \
  goal_x:=0.50 goal_y:=0.00 enabled:=true \
  max_speed:=0.20 max_acceleration:=0.50 \
  robot_radius:=0.18 safety_margin:=0.10 \
  emergency_stop_distance:=0.25
```

Ctrl-C 停止规划器后，看门狗会在原始指令超时后自动向底盘发零速度；为了保留这个保护，规划器停止
后应继续让看门狗进程运行。

## 6. 常用检查与调试命令

```bash
# 查看节点和话题
ros2 node list
ros2 topic list

# 查看关键话题类型、发布者和订阅者
ros2 topic info /scan --verbose
ros2 topic info /odom --verbose
ros2 topic info /cmd_vel --verbose

# 查看消息频率
ros2 topic hz /scan
ros2 topic hz /odom
ros2 topic hz /cmd_vel

# 单次查看传感器和规划输出
ros2 topic echo /scan --once
ros2 topic echo /odom --once
ros2 topic echo /imperative/planned_path --once

# 查看 odom 到激光坐标系的 TF；frame_id 以实际 /scan 消息为准
ros2 run tf2_ros tf2_echo odom laser

# 查看 Gazebo 仿真软件扫描和动态障碍物真值
ros2 topic echo /sim_scan --once
ros2 topic echo /imperative/dynamic_obstacles --once
```

如果实际激光帧名不是 `laser`，先执行 `ros2 topic echo /scan --once`，读取消息头中的
`header.frame_id`，再替换 `tf2_echo` 的第二个参数。实机控制器会使用该 TF 查找激光点到 `odom`
的变换。

## 8. 直接运行离线算法演示（不启动 ROS）

核心算法文件也可以作为独立 Python 程序运行，使用文件内部的仿真障碍物和 LiDAR：

```bash
cd /home/xinlei/Data/ROS/rosmaster-m1-project
python3 src/imperative_navigation/algorithm/Imperative_learning_2D_moving.py
```

该命令不连接 Gazebo、实机传感器或 RViz，仅用于快速观察算法本身的仿真结果；ROS 2 仿真和实机
部署应使用前面的 launch 文件。
