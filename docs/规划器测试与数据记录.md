# 规划器测试与数据记录

当前测试默认使用 Gazebo、新 M1 模型和软件雷达 `/sim_scan`。每次测试都会保存：

- `planner.csv`：目标点、规划位置、规划加速度、规划速度和实际里程计状态；
- `cmd_vel.csv`：发送给 Gazebo 底盘的速度命令；
- `odom.csv`：实际位置、速度和由速度差分估计的实际加速度；
- `scan.csv`：每一帧雷达的全部角度、距离和有效标志；
- `planned_path.csv`：RViz 中绿色预测路径；
- `obstacles.csv`：测试障碍物位置；
- `summary.json`、`metrics.json`：起点、终点、目标距离和统计指标；
- `plots/`：轨迹、速度/加速度、雷达质量图。

## 底盘执行预检

为了区分规划器和底盘，先启动不带规划器的仿真：

```bash
ros2 launch imperative_navigation imperative_m1_gazebo.launch.py \
  gui:=true rviz:=false software_lidar:=true planner:=false \
  move_obstacles:=false world:=imperative_m1_empty.sdf
```

另开终端发送固定速度：

```bash
ros2 topic pub -r 10 /cmd_vel geometry_msgs/msg/Twist \
  "{linear: {x: 0.1, y: 0.0}, angular: {z: 0.0}}"
```

同时观察：

```bash
ros2 topic echo /odom
```

如果 `/cmd_vel` 方向正确而 `/odom` 方向错误，应先检查底盘模型、麦轮插件或坐标变换，不应先修改规划器。

## 结果判断

- `planner.csv` 中规划速度方向错误：规划器问题；
- 规划器输出正确、`/cmd_vel` 正常、`/odom` 方向错误：底盘或坐标系问题；
- 实际速度明显滞后规划速度：底盘加速度和规划器模型不匹配；
- `scan.csv` 有效点数异常或最小距离长期等于量程下限：雷达输入问题；
- `summary.json` 中 `goal_reached` 为 `false`：该轮未在记录结束前到达目标。
