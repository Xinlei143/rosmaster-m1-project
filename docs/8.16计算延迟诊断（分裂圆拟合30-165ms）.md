# 8.16 计算延迟诊断（分裂圆拟合 30–165 ms）

## 1. 诊断目的

检查仿真小车在控制周期为 `0.1 s`、预测时域为 `1 s` 时，单个控制周期内各处理阶段的计算耗时，定位控制回调超过 `0.1 s` 的原因。

## 2. 测试条件

- 日期：2026-08-16
- 仿真：Gazebo headless 模式，关闭 RViz
- 激光：软件 LiDAR，`667` 条射线，`12 Hz`
- 动态障碍物：关闭
- 控制周期：`0.1 s`
- 轨迹预测时域：`1 s`
- 轨迹预测步数：`10`
- 测试期间使用较低的 `max_speed:=0.3`，以延长有效运动时间；该参数不影响激光检测耗时

测试使用的仿真启动参数：

```bash
ros2 launch imperative_navigation imperative_m1_gazebo.launch.py \
  gui:=false rviz:=false software_lidar:=true \
  dynamic_obstacles:=false goal_x:=3.5 goal_y:=2.5 max_speed:=0.3
```

## 3. 控制周期分解

完整控制回调包含以下阶段：

1. 激光预处理：过滤无效量程、转换为二维点并变换坐标；
2. 激光障碍物检测：聚类、圆拟合和必要的分裂拟合；
3. 轨迹跟踪：跨扫描帧关联检测结果并估计速度；
4. 地图更新：更新静态点云和动态点过滤结果；
5. 轨迹规划：评估候选速度轨迹；
6. 可视化和速度发布。

实测典型耗时如下：

| 阶段 | 典型耗时 |
| --- | ---: |
| 激光预处理 | `0.1–0.3 ms` |
| 激光聚类 | `9–35 ms` |
| 主圆拟合 | `0.5–2 ms` |
| 分裂圆拟合 | `30–165 ms` |
| 候选切分搜索 | `0.6–6 ms` |
| 轨迹跟踪 | `0.3–0.5 ms` |
| 地图更新 | `1–5 ms` |
| 轨迹规划 | `2.5–7 ms` |
| 可视化发布 | `<2 ms` |

完整控制回调的耗时从约 `55 ms` 逐步增加到 `100–180 ms`，偶发更高。因此控制器不能稳定保证每 `0.1 s` 完成一次完整计算，实际控制频率会下降到约 `5–8 Hz`。

## 4. 激光聚类

LiDAR 点按照扫描角度排列。程序从前往后检查相邻有效回波，满足以下任一条件时开始新的点簇：

- 两个有效回波之间存在缺失束；
- 相邻点的空间距离大于 `CLUSTER_GAP = 0.30 m`。

因此，聚类的作用是把整帧激光点分成若干段，每段通常对应一个障碍物表面或墙面片段。扫描首尾还会进行一次环回检查，避免 `-π` 和 `π` 附近的同一物体被错误分成两簇。

原实现位于算法文件的 `scan_to_detections()`；当前已替换为
[`scan_to_cluster_detections()`](../src/imperative_navigation/algorithm/Imperative_learning_2D_moving.py)。

## 5. 普通圆拟合

程序默认将一个点簇解释为半径约 `0.30 m` 的圆形障碍物。它使用最小二乘方法估计圆心，然后计算所有点到圆心的距离与 `OBSTACLE_RADIUS` 的残差。

当平均残差不超过：

```text
CIRCLE_FIT_MAX_ERROR = 0.02 m
```

该点簇就被视为一个圆形障碍物，并输出一个障碍物中心，用于后续跨帧关联和动态速度估计。

原 `_fit_circle_lstsq_points()` 和 `CIRCLE_FIT_MAX_ERROR` 判断已从当前代码删除；需要复核旧实现时
应查看本次修改之前的 Git 历史。

需要注意：即使圆拟合失败，原始激光点仍会继续用于地图和碰撞检测；圆拟合主要服务于障碍物中心提取和动态跟踪。

## 6. 分裂圆拟合和候选搜索

当一个点簇整体不像单个圆时，程序认为它可能包含两个相邻物体，或者包含墙面与圆形障碍物的混合回波。

对于包含 `N` 个点的点簇，程序尝试切分为：

```text
点 1 ... 点 k | 点 k+1 ... 点 N
```

候选位置从 `k = 3` 到 `k = N-3`，确保左右两边至少各有三个点。每个候选位置都需要计算左、右两个子簇的圆拟合误差，然后选择总误差最小的位置。

只有当分裂后的误差显著改善时才接受分裂：

```text
best_error < 0.50 × original_error
```

这里要区分两个耗时：

1. 分裂圆拟合：为所有候选切分位置计算左右子簇的拟合误差；
2. 候选搜索：遍历已经算好的误差数组，找出误差最小的切分位置。

本次重新计时后，两者不再重叠。结果显示，主要耗时是第一项：

- 分裂圆拟合：`30–165 ms`；
- 候选搜索：通常只有 `0.6–6 ms`。

原 `_split_candidate_indices()`、`_split_circle_errors_prefix()` 和 `pending_clusters` 分裂处理流程均
已从当前代码删除；本节保留其历史性能数据。

## 7. 延迟增长原因

测试过程中通常检测到约 `5` 个初始点簇，但某些点簇包含大量连续墙面回波。由于整簇点无法被一个半径 `0.30 m` 的圆解释，程序进入分裂流程。

候选切分数从约 `520` 增加到 `900+` 时，分裂圆拟合耗时明显增加：

```text
约 520–650 个候选：约 30–80 ms
约 700–900+ 个候选：约 100–165 ms，偶发超过 200 ms
```

分裂误差计算需要构造大量候选切分对应的左右子簇残差，计算量随点簇规模快速增长。因此，控制周期变慢的主要原因不是轨迹规划，而是大规模墙面点簇触发的分裂圆拟合。

## 8. 当时提出的优化方向

建议按以下优先级处理：

1. 对超大点簇设置分裂上限，避免墙面点簇尝试数百个切分位置；
2. 对墙面或近似直线点簇先做直线/墙面识别，跳过圆拟合；
3. 对激光点进行适度降采样，同时保留近距离点用于安全碰撞检测；
4. 只在收到新 LiDAR 帧时执行聚类和圆拟合，避免控制周期重复处理同一帧；
5. 将激光检测从控制回调中拆出，控制器使用最近一次检测结果；
6. 原始激光点继续保留给碰撞检测，优化只针对动态障碍物中心提取流程。

以上内容记录的是删除圆拟合之前的诊断结果，用于解释原始延迟来源。

## 9. 处理结果：删除圆拟合并改用 Kalman 跟踪

本次修改已从在线感知链路中删除以下计算：

- 最小二乘主圆拟合；
- 分裂位置生成和分裂圆拟合；
- 分裂候选搜索和对应的 fallback；
- 固定 `0.30 m` 拟合半径对 detection 中心的约束。

新的链路为：

```text
LaserScan
  → 相邻点聚类
  → 质心 + P90 尺寸估计
  → 大跨度墙面点簇过滤
  → 全局最近邻数据关联
  → [x, y, vx, vy] 匀速 Kalman Filter
  → 未来 1 s 位置预测
```

点簇半径采用“点到质心距离 P90 + `0.08 m`”，并限制在 `0.10–0.60 m`；跨度超过 `1.20 m`
的点簇不进入动态跟踪。该过滤不会删除原始 LiDAR 点，墙面和大型障碍物仍参与每个控制周期的
静态碰撞检测。

Kalman 跟踪使用 `0.08 m` 位置观测噪声、`0.8 m/s²` 过程加速度噪声和 `0.80 m` 关联门限。
规划器、动态地图点清理和 RViz 标记均使用每条轨迹自身估计的半径，不再统一假设跟踪目标为
固定大小。

仿真、实车适配器和独立算法示例的默认控制周期均为 `0.1 s`，预测步数均为 `10`，即默认预测
时域统一为 `1 s`。

## 10. 修改后的验证结果

修改后使用软件 LiDAR、3 个动态障碍物、`max_speed:=0.3` 进行 headless Gazebo 测试。仿真连续运行
超过 `300` 个 `0.1 s` 控制周期，控制器没有出现检测、关联或规划异常。控制器每 1 秒输出一次诊断，
共取得 `31` 个均匀抽样回调：

| 阶段 | 平均 | P95 | 最大 |
| --- | ---: | ---: | ---: |
| 完整控制回调 | `24.7 ms` | `30 ms` | `31 ms` |
| 点簇检测 | `13.4 ms` | `17 ms` | `19 ms` |
| Kalman 跟踪与关联 | `0.94 ms` | `1 ms` | `1 ms` |
| 地图更新 | `3.77 ms` | `7 ms` | `7 ms` |
| 轨迹规划 | `5.10 ms` | `8 ms` | `9 ms` |
| 可视化发布 | `1.23 ms` | `2 ms` | `3 ms` |

点簇检测耗时现在主要来自原有的逐束聚类循环，几何中心和 P90 半径计算通常低于日志的 `1 ms`
显示精度。原来的分裂圆拟合阶段已经完全消失，完整回调最大抽样耗时 `31 ms`，低于 `100 ms`
控制周期，未再出现 `100–200+ ms` 尖峰。
